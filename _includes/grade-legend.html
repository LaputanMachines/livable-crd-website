{%- comment -%} The grading key: four letters and the states that are not letters. Rendered directly above the grades it explains, on the scorecard matrix and on every candidate page. Three of those states are drawn only when something below is in them. `legend_states` in _plugins/questionnaire_scores.rb walks the published data with the templates' own rule and says which chips the pages draw; the key names those and no others, so it cannot explain a mark a reader will not find. The dash is unconditional: somebody has always failed to reply. The hourglass is the exception in the other direction — it is drawn on the page and deliberately left out of the key; see below. A shared include rather than the same markup in two places. The two empty states are the ones a reader most easily misreads — a returned questionnaire drawn like a no-show — and a key that says one thing on the scorecard and another on a candidate page is worse than one key in one place. Every chip comes from grade-badge.html, the same call the table and the topic rows make, so the key cannot end up showing a mark the grades below it do not. An empty `grade` is what puts that include into an empty state; `state` picks which of the four. {%- endcomment -%} {%- comment -%} C- is filtered out here the same way the homepage hero strip filters it (index.md), and for the same reason: a fourth letter chip between C and F crowds a key that a reader scans rather than studies. It stays in _data/grades.yml with its label, description and colour, so the grade is still one the coalition can award and grade-badge.html still draws it. The trade that comes with that: if a published grade ever is a C-, the key above it will not name that mark. No score currently carries one, so nothing on the site is unexplained today — but this is a filter on presentation, not a retirement of the grade, and the scorecard's UX pass is the place to decide whether the key should show the letters in use rather than a fixed list. {%- endcomment -%} {%- comment -%} Each non-letter item carries its own modifier class, so a page that cannot draw that mark can drop it from the key: the candidate leaflet hides the answered speech bubble, because print leaves out both the topics that carry one and the answers behind them. See the @media print block in _sass/_candidate.scss. The declined bubble is not among those: its topics are ordinary graded rows that the leaflet prints, so the key has to name it there too — and since the answered one is gone by then, a bubble on paper is unambiguous. {%- endcomment -%} {%- assign legend_grades = site.data.grades | where_exp: "grade", "grade.letter != 'C-'" -%}
